# VPS 配置建议（初步）

需求记录：

- 直播路数：1 路
- 用途：scheduled（计划/定时直播）
- 月预算：约人民币 150 元
- 部署方式：Docker
- 推流平台：当前计划以 YouTube 为主

## 建议起步配置

| 项目 | 建议 |
|---|---|
| CPU | 2 vCPU |
| 内存 | 2 GB RAM |
| 系统盘 | 30–40 GB SSD 起步；本地视频素材多时需更大 |
| 网络 | 优先稳定持续上行；1080p 常见视频流约 3–6 Mbps，建议留出余量，目标至少 10–20 Mbps 可持续上行 |
| 系统 | Ubuntu 22.04 / 24.04 LTS |
| 软件 | Docker Engine + Docker Compose Plugin |

以上是单路、以视频直推/不转码为前提的起步建议，不是对任意码率、任意转码任务的保证。

## 选购时的优先级

1. 稳定的持续上行带宽和到 YouTube RTMP 的连通性。
2. CPU/内存资源不超售、磁盘 I/O 稳定。
3. 线路和机房的实际表现。
4. 月付价格和流量限制。

## 关于 CN2

CN2 等线路标签主要描述 VPS 与中国网络之间的路由表现，不能单独证明 VPS 到 YouTube RTMP 的出站链路一定更好。购买前应确认带宽是独享还是共享、月流量上限、超流量策略，并在试用/退款期实测推流稳定性。

## 何时需要升级

- 如果只做 `copy` 直推、不进行视频转码，2 vCPU / 2 GB 通常可以作为单路测试起点。
- 如果启用 H.264 等实时转码、滤镜或多路推流，CPU 需求会明显增加，建议重新评估 4 vCPU 及以上配置。
- 如果把大量视频上传到 VPS 本地循环播放，系统盘容量应按素材总大小另行增加。

## 尚待实测

- 实际视频分辨率、帧率和码率
- 是否需要实时转码
- VPS 到 YouTube ingest 的稳定性
- 项目是否原生支持按具体时间自动启动/停止视频推流

不要只凭“CN2”或超低年付价格决定生产环境服务器。
